# Threat model

## What are we building?

A multi-tenant job service. Tenants submit documents, jobs run and commit results, and every step is recorded in a per-job hash chain that can be replayed. One tenant must never read or change another tenant's data, and must not be able to tell whether another tenant's data exists.

**Assets**
- Tenant rows in `documents`, `document_versions`, `jobs`, `attempts`, `artifacts`, `outbox`, `processed_events`, `audit_events`, `cap_grants`, `job_checkpoints`, `extractions`, `extracted_facts` and `extraction_dead_letters`.
- Per-tenant content bytes at `tenants/{tenant}/{sha}`.
- Capability grants, which authorize every commit.
- Each job's audit chain and checkpoints.
- The model credential (`ANVIL_MODEL_API_KEY`), which spends the operator's model allowance.

**Trust boundaries** (marked in `docs/architecture/containers.mmd`)
1. **HTTP entry.** Tenant clients send untrusted requests and documents.
2. **Database.** Every query runs as the runtime role under row-level security.
3. **Exec jail.** Tenant-supplied commands run here, inside a bubblewrap sandbox. No production code calls it yet.
4. **Network egress** through the parent's `JailEgress` broker. The jailed child has no network of its own.
5. **Content store.** Files on disk, reached through presigned URLs.
6. **Model provider.** Extraction sends the first 500 characters of a tenant's document to an external Anthropic-compatible API over HTTPS, and treats the reply as untrusted input (record 0022).

## What can go wrong?

- **A forged or missing tenant identity** reads or writes another tenant's rows.
- **Connection-pool reuse or a cached plan** leaks rows across tenants.
- **Cross-tenant IDs, search cursors or content hashes** reveal whether another tenant's data exists (an oracle).
- **A stale or zombie worker** commits after its lease moved on, or a revoked capability still commits.
- **A tenant floods the queue** and holds the worker pool, so other tenants' jobs wait behind it.
- **A database restore** rewinds fencing tokens and capability grants, so a worker from the lost timeline holds a token or grant that the restored database issues again.
- **Path traversal or symlinks** in content paths or workspace files escape the tenant's directory.
- **A presigned URL** is swapped to another tenant, tampered with, replayed after expiry, or used after its capability is revoked.
- **Audit chain tampering:** an event is edited, deleted, forked or dropped, and replay reports a false match.
- **Jailed code** reads a sibling workspace, inherits secrets through environment variables, floods output, or reaches the network (metadata endpoints, internal addresses, redirects).
- **Unbounded input:** oversized titles, bodies or keys.
- **Model output:** a citation invented or paraphrased, a value the cited text doesn't hold, an instruction hidden in a document steers what is emitted, malformed output gets indexed, or a new prompt or model is quietly worse.
- **Extraction across tenants:** a forged or other tenant's document ID is extracted or reveals that the document exists, or a shared result, cache or dedup key lets one tenant's extraction answer another's.
- **Poison input:** binary, empty or control-character content, or a document built to make the model refuse or emit junk, gets indexed or blocks the tenant.
- **Tenant text leaves the system:** the provider keeps or trains on what it's sent, or the credential leaks.
- **The eval set is edited or tuned on,** so the gate stops measuring.
- **A secret is committed,** or a dependency or CI action is compromised.

## What will we do about it?

| Threat | Control | Proven by |
| --- | --- | --- |
| Forged or missing tenant | `TenantAuthFilter` requires `X-Tenant-Id` on submit, read, audit and replay paths, and looks it up in `tenants`. Missing or unknown returns `401`; a failed lookup fails closed. `SubmitService` re-checks the tenant inside its transaction. Tenant query parameters are ignored. | `SubmitIdempotencyTest.missingOrUnknownTenantIsUnauthorizedWithNoRows`, `AuditReadIsolationTest.forgedTenantParamIgnored` |
| Cross-tenant rows | `RLS FORCE` with one `tenant_isolation` policy per tenant table (`tenant_id = current_setting('app.tenant', true)`). Runtime role `anvil_app` is `NOSUPERUSER NOBYPASSRLS`. Views are `security_invoker`. `TenantGuard` sets `SET LOCAL app.tenant` with a read-back probe, so a missing context reads 0 rows. Composite foreign keys keep references inside one tenant. | `RlsLeakTest`, `DurableV1SchemaTest.crossTenantReferencesRejected` |
| Existence oracle | Direct-ID reads, prefix search, audit reads and content reads filter by tenant, run under RLS, and re-check every row. A cross-tenant ID looks exactly like a missing one (empty result or a generic `404`). A foreign cursor yields 0 rows. | `ReadIsolationTest` (28 cases), `AuditReadIsolationTest`, `ReplayTest.crossTenantDenyFailClosed` |
| Stale worker, revoked capability | Every mutation is fenced on `(id, tenant_id, owner, fencing_token, state)` with the database clock. A commit also needs a current, unrevoked, unexpired capability grant, checked in the same transaction. Denial affects 0 rows, returns `403 NEEDS_APPROVAL`, and counts `cap_rejected`. Terminal rows are immutable. | `JobServiceTest`, `CapRevokeMidRunTest`, `FaultProofTest`, `FaultMatrixTest` |
| Tenant flood | Every claim takes the tenant's advisory lock, counts its `RUNNING` jobs and claims nothing at `tenants.max_running`. `claimNext` ranks tenants by `(penalty, next_run_at, created_at, id)`, where the penalty is the tenant's `RUNNING` count, so a worker that frees up goes to the tenant running fewest jobs. Only jobs due on the database clock are claimed. `claimNext` reads every tenant's head job and count, one tenant context per statement. Record 0020. | `FairClaimTest`, `RlsLeakTest.claimNextClaimsEachTenantsJobUnderThatTenantsContext` |
| Restore rewind | `db_timeline` stores the confirmed `(system_identifier, timeline_id)`, and a restore rewinds it while Postgres moves to a new timeline. Claim, heartbeat and commit refuse (`503 TIMELINE_UNCONFIRMED`, 0 rows) while it doesn't match the server's or can't be read. `confirmTimeline` reopens only once no lease is live on the database clock. It raises every open job's token by `max_attempts` and deletes every grant, so each commit waits for a re-issued grant with a new id. Confirm is database-wide: any tenant's claim can run it, and it changes every tenant's tokens and grants. `anvil_app` can write `db_timeline`, so the gate detects restores; it isn't a control against the runtime role. | `PitrTimelineCheckTest`, `PitrRestoreDrillTest` |
| Path escape | Tenant names that contain `/`, `\`, `..`, `%`-encoding or reserved names are rejected. Every content read re-hashes the bytes and never serves a torn tail. `ContentStore.getForCaller` needs caller = owner plus an `artifacts` row, otherwise it returns a caller-scoped `404`. | `ContentStoreTest.rejectsTraversalAndBadShaWithoutEscapingRoot`, `ContentStoreTest.tornTailDetectedAndRemovedRatherThanServed` |
| Presigned URL abuse | HMAC bound to tenant, sha, job, capability, epoch and expiry; 60-second lifetime on the database clock. A swapped tenant, tampering, expiry or a revoked capability returns `403`. | `ReadIsolationTest` |
| Audit tampering | Appended in the same transaction as the effect. `UNIQUE(job_id, seq)` and `UNIQUE(job_id, prev_hash)` block forks. Immutability triggers block edits and deletes, and the runtime role can only `SELECT` and `INSERT`. Replay recomputes the chain and reports a mismatch, never a silent success. Replay itself writes nothing. | `AuditChainTest`, `ReplayTest` |
| Jail escape | Every child runs under bubblewrap with new user, mount, PID, IPC, UTS, cgroup and network namespaces and no capabilities. It sees only read-only `/usr`, a private `/tmp`, a fresh `/proc` and its own workspace at `/work`. Sibling workspaces, the host `/tmp`, `/etc` and host processes don't exist there, so native code, interpreter `-c`, workspace binaries, `/proc` and symlinks can't reach them. A missing or blocked sandbox refuses to run. Workspace reads and writes wait for the tenant's running child, so jailed code can't race the parent's symlink check. The environment is cleared to `PATH` and `ANVIL_TENANT` plus an allowlist, and loader or debug keys are denied. Argv checks stay as defence in depth. Output is capped at 1 MiB per stream, with a 30-second timeout that kills the whole tree. `readWorkspaceFile` denies cross-tenant callers before any lock or file access, in the same time whether the file exists or not. Record 0019. | `ExecJailTest.nativeCodeCannotReachSiblingWorkspaceOrSharedTmp`, `ExecJailTest.everyNamespaceIsNewAndNoCapabilityIsHeld`, `ExecJailTest.sandboxUnavailableFailsClosed`, `ExecJailTest.workspaceApiWaitsForRunningChild`, `ExecJailTest.timeoutKillsEveryJailedProcess`, `ExecJailTest.deniedWorkspaceReadTimingHidesExistence`, `JailContainerEscapeTest` |
| Jail egress | The child's network namespace has only its own loopback and no routes, so the kernel drops every packet to another host. The only way out is `JailEgress` in the parent. It allows only HTTPS, with SNI and host-name verification, and denies anything not allowlisted without resolving DNS. It decodes IP literals (including non-canonical and IPv6-mapped forms) and denies loopback, metadata, link-local, private, carrier-grade NAT and reserved addresses; for IPv6 it passes only global unicast. It resolves allowlisted names again at connect time, denies if any answer is blocked, and connects to the vetted address. It denies every redirect. A denial gives only a generic reason and takes the same time whether the target exists or not. | `ExecJailTest.jailEgressDroppedAtNetworkLayer`, `ExecJailTest.hostnameRebindDeniedAtConnect`, `ExecJailTest.ssrfMatrixAllDenied`, `ExecJailTest.redirectNotFollowed`, `ExecJailTest.tlsConnectorVerifiesCertificateAndHostName`, `ExecJailTest.deniedEgressTimingHidesExistence`, `JailContainerEscapeTest` |
| Model output | `EvalGate` scores every candidate against the frozen set `eval/sets/pilot-v1` and its baseline, in the gate's `eval` job. It fails when the paired F1 difference interval lies wholly below 0, when attacks in the 12-case injection subset succeed more often than against the baseline, or when any citation isn't an exact substring of its document (`CitationCheck`, which #37's acceptance requires of every emitted citation). Record 0021. | `EvalGateTest`, `CitationCheckTest`, `EvalStatsTest` |
| Extraction output | There is one path, `Extractor.extract`, used by the service and the harness; it is the only caller of `ExtractionModel.complete`, which takes only a `BoundedText`, so no more than 500 characters of a document reach the model. The document sits between markers with a random value per call, and the reply is constrained to a JSON schema. A fact is indexed only when its field is one of four, its citation is a non-empty exact substring of the text the model saw (`CitationCheck`) and its value is in its citation. Anything else goes to `extraction_dead_letters`. Malformed output, a refusal or a cut-off reply quarantines the whole document. `EvalGate` scores harness runs as below. Record 0022. | `ExtractorTest`, `ExtractHarnessTest`, `ExtractionIsolationTest.aFactThatFailsTheCitationCheckIsDeadLetteredAndNeverServed` |
| Extraction across tenants | Both routes take the tenant only from `X-Tenant-Id`. A forged, malformed, missing or other tenant's ID gets the same `404` and body, before any model call. Reads and writes set the tenant per transaction and run under RLS `FORCE` on the three new tables. A version's result is keyed by `(tenant_id, version_id)`, so identical content in two tenants is extracted separately; there is no shared cache or dedup. The model adapter keeps no state between calls and sends no tenant identifier. | `ExtractionIsolationTest`, `RlsLeakTest` |
| Poison input | Non-text media types, empty text, control characters and invalid UTF-8 are quarantined without a model call. A malformed or refused reply quarantines the document. Each dead letter keeps its reason and, for a fact, the rejected fact; for malformed output, up to 2000 characters of it. No route reads `extraction_dead_letters`. A quarantined version stays quarantined. A model outage is not poison: nothing is stored and the request can be retried (`503`). | `ExtractionIsolationTest.aPoisonDocumentIsQuarantinedWholeAndServesNoFacts`, `ExtractionIsolationTest.noRouteReadsDeadLetters`, `ExtractionIsolationTest.aModelOutageStoresNothingAndALaterRetrySucceeds` |
| Tenant text sent to the provider | Only the first 500 characters of a text document leave, over HTTPS to an operator-configured base URL that must be `https`; it is never tenant input. The credential is read from the environment, never logged, stored or committed (`.env` is untracked). Without one, extraction answers `503` and sends nothing. | `ExtractorTest.theAdapterNeedsHttpsAndACredentialBeforeAnyCall`, the `gate` check (gitleaks) |
| Eval set edited or tuned on | `EvalSet.load` refuses a set whose files don't match the SHA-256s in its manifest, or that holds a duplicate, near duplicate or over-long document. `task test:contract:eval` fails when a file under `eval/sets/` is edited or removed. The manifest's never-tuned-on rule retires a set that's been tuned on, and no 8-word run of the set may appear under `src/main`. | `EvalSetTest`, the `gate` check |
| Unbounded input | `SubmitService` limits title, `mime_type`, `Idempotency-Key` and body. Canonical CBOR covers only `{title, mime_type, body}`. | `SubmitIdempotencyTest.invalidPayloadLeavesZeroRows` |
| Secrets and supply chain | No secret values in the repo; Compose reads `POSTGRES_PASSWORD` from the environment. The gate scans full git history with gitleaks, fails on newly added vulnerable dependencies, and pins CI actions to commit SHAs. GitHub push protection blocks secret pushes. Logs are JSON with correlation IDs and no secrets. The scheduled `faults` workflow's build and test jobs keep a read-only token. Only its report job, which runs no build or tests, can write issues, and it writes only the failed run's seed and trace. | The `gate` check, `FaultScheduleTest` |

## Did we do enough?

Not fully. These risks are accepted for now:

- **The jail has no syscall filter or resource limits** (record 0019). A kernel exploit from inside the sandbox, a fork bomb or memory exhaustion isn't contained. The host must allow unprivileged user namespaces. In a container, that means relaxed seccomp and AppArmor profiles and unmasked `/proc` paths, which the production image doesn't have yet. The tenant lock is per JVM.
- **The leak matrix leaves out sweeps.** `RlsLeakTest` interleaves two tenants on one pool across all 13 tenant-scoped tables and the submit, claim, fair claim (`claimNext`), heartbeat, commit, capability, relay, read, search, audit read, replay and CAS paths (#74). Reconcile and garbage collection sweep every tenant by design and aren't in the matrix. `claimNext` sweeps every tenant too, but the matrix runs it as the restricted role.
- **Fair claim limits** (record 0020). The default quota (1000) caps nothing until an operator sets one, so without it fairness comes only from the penalty. The quota counts jobs, not their cost. Under many workers the order is best-effort (one ranking snapshot, the penalty isn't re-read at claim time); the quota is exact. `claimNext` time grows with the number of tenants, and one tenant's claims serialize on its lock.
- **Eval gate limits** (record 0021). With 40 documents, a candidate worse on 3 documents and better on none passes; one worse on 4 or more fails. A candidate better on some documents and worse on others can lose F1 and still pass. The attack check compares counts with a baseline fooled in 3 of 12 cases, so it allows up to 3. The set is short English text with four fields, and its author knew the baseline's rules, so the baseline's score is biased low. The never-tuned-on rule is mostly procedural: the 8-word check can't see paraphrased examples or rules derived from the set.
- **Extraction limits** (record 0022). Injection cases the harness run shows succeeding are listed in record 0022 with repro, behaviour and containment; the prompt and checks can't stop a planted value that is also a plausible fact, written in the document and cited exactly. Requests go to a third party: the configured provider (OpenCode Go serving `claude-haiku-5-5`) keeps requests for 30 days under Anthropic's policy, and OpenCode Go's terms describe it as made for coding agents, so serving tenant traffic needs a provider whose terms cover it. There is no budget, cache or kill-switch yet (#38). The model call holds the HTTP request for up to 30 seconds per attempt with 2 retries. A version quarantined for a one-off malformed reply stays quarantined.
- **Replay cost grows with chain length** (#76). Replay re-verifies the whole chain, so a long chain makes it slow (chain DoS).
- **Some restores aren't detected** (#34, record 0016). A storage snapshot rolled back in place, or a base backup started without `recovery.signal`, keeps the timeline, so the gate stays open. Effects outside the database from after the restore target can repeat, and the old primary must be gone before the restored one serves.
- **A time-of-check gap after each grant check.** A revoke that lands after a commit's grant check takes effect from the next commit.
- **Some steps aren't logged:** heartbeat, reclaim, empty polls and `outbox.sent_at`. Replay's output is the same without them.
